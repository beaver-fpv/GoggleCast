# 观幕 GoggleCast 常见问题

[返回项目主页](../README.md) · [眼镜兼容性](COMPATIBILITY.md) · [完整使用说明](USAGE.zh-CN.md)

先确认三个条件：**眼镜在无线投屏等待页面、电脑与眼镜处于同一局域网、桌面和转码模式已有可用 FFmpeg。** 推荐完整离线 Setup 已包含编码器，便携版需要自行准备。每次改变设置或眼镜连接状态后，先停止当前投屏，再重新搜索和开始。

## 先确认型号是否适用于本项目

- **Goggles 3：已实机验证。** 下文的已验证画面与声音结果均来自此型号。
- **Goggles 2：可尝试，未实机验证。** [DJI 官方支持页](https://www.dji.com/support/product/goggles-2) 明确支持 DLNA 无线投屏，协议上具备尝试基础；本项目没有该型号的实机结果，不能保证发现、播放、声音或稳定性。
- **Goggles N3：不列入当前支持范围。** 当前核对的官方资料未记载 DLNA 无线投屏接收。[DJI N3 官方支持页](https://www.dji.com/support/product/goggles-n3) 中的 USB 接手机分享飞行画面是眼镜向外输出，不能据此判断它能够接收电脑桌面。

详细依据与适用边界见 [眼镜兼容性说明](COMPATIBILITY.md)。

## 离线安装失败或提示缺少运行环境

`GoggleCast-0.1.0-Setup.exe` 是完整离线安装包，包含应用和固定版 FFmpeg，安装过程不向上游下载文件。下载完整 Setup 后，可以在断开互联网的电脑上安装。

1. 确认系统为 Windows 10 / 11 x64，并已具备 **.NET Framework 4.8**。旧版 Windows 缺少此环境时，先准备并安装相应的 .NET Framework 离线运行库；Setup 不包含整个系统运行环境。
2. 确认下载的是完整 Setup，而非便携 ZIP 或另一个旧副本。如果下载损坏，重新从仓库 Releases 获取完整附件，并与发行页校验信息核对。
3. 检查安装位置是否可写、磁盘空间是否足够。安装按当前用户进行，不需要管理员权限，但不能写入未授权目录。
4. 保留安装错误信息用于反馈，不要通过替换同名依赖或关闭系统防护来掩盖失败。

安装成功仍提示缺少编码器时，确认运行的是刚安装的程序，而不是之前解压的便携副本，并检查 `runtime/ffmpeg.exe` 是否被移动或删除。怀疑随包编码器损坏时，关闭程序，重新运行完整 Setup 到原目录，从包内恢复运行文件即可，无需互联网。

运行目录中的 `runtime-source.json` 可用于查看 FFmpeg 来源、版本和上游压缩包 SHA-256。这些来源地址用于记录构建材料，不表示用户安装时会连接下载。

## 找不到眼镜

1. Goggles 3 打开「更多 → 无线投屏」，保持眼镜唤醒并停留在等待页面。尝试 Goggles 2 时，进入其无线投屏页，具体路径以该型号、当前固件手册为准；本项目没有验证其固件菜单。
2. 检查电脑和眼镜是否连接同一局域网。眼镜连接电脑移动热点时，确认热点仍然开启。
3. 避免路由器访客网络和客户端隔离。电脑接网线也可以，但必须与眼镜 Wi-Fi 所在网络互通。
4. 检查 VPN 或其他虚拟网卡是否改变了局域网路由。
5. 若 Windows 防火墙提示网络访问，请仅在信任的专用网络允许本程序；不要为排查而关闭整个防火墙。
6. 重新点击「搜索设备」。仍不出现时，输入眼镜当前 IPv4 地址进行定向搜索，或输入已知的设备描述文件 HTTP 地址。

重新连接 Wi-Fi、重启眼镜或重新进入无线投屏后，**IP 和服务端口都可能变化**。旧的列表项或描述地址可能已失效，请重新搜索。手动输入 IP 不能绕过隔离的网络，也不能唤醒未开启的投屏服务。

## 能发现设备，但连接超时

发现设备只说明搜索收到了响应，后续控制和媒体连接仍可能失败。

- 保持眼镜唤醒，停在无线投屏等待页面。
- 点击停止；在眼镜端退出并重新进入无线投屏，再搜索最新设备。
- 如果更改过网络、热点或眼镜连接状态，使用新搜索到的记录，不复用旧地址。
- 先用「测试画面」和 MPEG-TS 验证连接，排除文件和桌面输入的影响。
- 展开「连接日志」查看具体是发现失败、控制请求失败、未收到媒体请求，还是编码失败。

不要仅凭设备报告 `PLAYING` 判断画面成功；请以眼镜实际显示为准。

## 软件显示发送中，眼镜没有画面

先等待接收端完成数秒缓冲，再按下面顺序尝试：

1. 停止，改选「测试画面」重新开始。
2. 如果测试图可见，桌面或文件输入可能有问题；如果测试图也不可见，优先检查网络和接收端。
3. 将「自动（优先 NVIDIA）」改为「软件编码」。
4. 停止后，将 MPEG-TS 改为分片 MP4，或反向切换。
5. 本地视频取消「MP4 原画直传」，使用默认兼容转码。
6. 如仍无画面，在眼镜端重新打开无线投屏，并重新搜索设备。

日志中有媒体请求但没有输出数据，通常应继续查看 FFmpeg 或输入错误。只有控制状态、没有来自眼镜的媒体读取请求时，应检查眼镜能否访问电脑选定网卡和程序的局域网媒体服务。

## 找不到 FFmpeg / 编码器无法启动

推荐 Setup 正常安装后无需手动配置 FFmpeg。若使用便携版、源码构建或编码器被移走，请自行准备 Windows 构建，再展开「编码器路径」选择真正的 `ffmpeg.exe`，不要选择压缩包、下载页面或文件夹。

可检查：

- 路径中的文件是否仍存在，是否被移动或删除。
- 构建是否包含 `gdigrab`、`libx264` 和 AAC 编码器。
- 手动选择「软件编码」是否可启动。
- 使用 NVIDIA 时，构建是否包含 `h264_nvenc`，显卡和驱动是否可用。
- 电脑是否允许该 FFmpeg 可执行文件运行。

自动模式会尝试探测 NVENC 并回退 CPU，但无法补齐缺失的 FFmpeg 编码器或修复损坏文件。日志中的 FFmpeg 原文是进一步诊断的依据。

## 画面正常，眼镜耳机没有声音

1. 确认耳机接在 **眼镜**，并按具体型号检查接口：Goggles 3 使用 USB-C 数字 DAC 耳机或兼容转接头，没有内置扬声器；Goggles 2 使用 **3.5 mm 耳机接口**，其投屏音频功能见 [DJI 官方支持页](https://www.dji.com/support/product/goggles-2)。GoggleCast 的 Goggles 2 音频路径尚未实机验证。
2. 桌面模式检查「发送桌面系统声音」已勾选。
3. 确认电脑上正在播放有声内容，且其输出在 Windows 默认播放设备；被单独分配到另一设备的应用可能不在当前回环采集内。
4. 如果刚改变 Windows 默认播放设备，停止投屏，再重新开始。
5. 本地视频先使用兼容转码，确认源文件存在可读取音轨。原画直传的声音取决于眼镜对原始音轨的支持。
6. 用「测试画面」检查提示音，区分耳机/接收端路径与桌面声音问题。

程序不采集麦克风；桌面声音也不会自动包含所有播放设备。

## 声音比画面早 / 感觉有延迟

先确认从哪里听声音：

| 收听路径 | 应如何处理 |
| --- | --- |
| 电脑耳机或电脑扬声器 | 电脑声音没有眼镜的接收缓冲，可能早于眼镜画面。请改用眼镜连接的耳机。此版本没有电脑耳机延迟补偿。 |
| 眼镜连接的耳机 | 音视频来自同一媒体流。停止并重新开始，确认默认音频设备和源文件正常；若持续偏移，记录具体模式和复现步骤。 |

如果眼镜里的口型和声音一致，只是同时晚于电脑，这是整体投屏缓冲。项目没有宣称零延迟，也没有精确毫秒级误差或长期漂移测量。

实机已确认一台 Goggles 3 上的桌面系统声音及兼容转码视频主观同步正常，但这不能替代其他电脑、固件、网络与耳机路径的验证。

## 视频能转码，但原画直传无法播放

直传意味着文件保持原样，眼镜必须直接支持其视频编码、尺寸、封装和音轨。MP4 扩展名并不保证接收端可解码。

取消「MP4 原画直传」即可回到默认 H.264 / AAC 兼容转码。转码会按所选清晰度等比缩放并加必要黑边，保留第一条可读取音轨。换新文件时，软件也会恢复兼容转码默认值。

## 视频重复播放，或者不能拖进度

兼容转码模式当前会循环播放，点击「停止」结束。原画直传播放到文件末尾。当前界面没有进度条、字幕选择、音轨选择或播放列表。

## 卡顿、断流或电脑负载较高

- 优先使用稳定且设备能够互相访问的无线连接，缩短设备与接入点的距离。
- 先把清晰度降为 720p / 30 帧，观察是否改善。
- 自动模式可使用可用的 NVENC，减少 CPU 编码负担；硬件编码异常时，使用软件编码排查。
- 关闭不需要的重负载程序，并检查电脑是否同时进行下载或其他占用局域网的任务。
- 用测试画面对比。仅桌面或某个文件出问题时，查看对应输入和编码日志。

接收端正常缓冲和持续卡顿是不同现象。改变设置后先停止重启，避免在失效的旧会话上反复判断。

## Windows 提示未知发布者或 SmartScreen

当前发行版未进行 Windows 代码签名。确认下载来自本仓库的 Releases，且你决定运行该文件后，可在 SmartScreen 提示中选择「更多信息 → 仍要运行」（若该选项可用）。不需要关闭整个 SmartScreen 或系统安全防护。

如果电脑由组织策略管理，或系统没有提供继续运行选项，请遵循该电脑的管理要求；也可以查看源代码和构建说明。

## 程序打不开 / 只复制了 EXE

- 确认系统为 Windows x64，并装有 .NET Framework 4.8。
- 安装版请从其快捷方式启动；便携版完整解压，保留 `MainWindow.xaml` 在 `GoggleCast.exe` 旁。
- 将整个文件夹放到当前用户可写的位置。程序需要写入语言设置和诊断日志。
- 若产生 `startup-error.txt`，查看该文件；分享前先删除个人路径等信息。

## 语言切换后重启又恢复

语言偏好和选择的 FFmpeg 路径保存在程序旁的 `settings.xml`。如果该目录不可写、文件只读，或者启动的是另一个解压副本，设置可能未保存或未从原位置读取。界面会在保存失败时提示，日志中也保留原因。

原始 FFmpeg、设备和 Windows 技术诊断保留其原文，不代表界面语言设置失效。

## 升级后设置变化 / 找不到原来的快捷方式

升级前先关闭程序，运行新版 Setup 并使用原安装位置，以保留 `settings.xml` 中的语言与编码器路径。如果使用新目录或启动了另一个便携副本，其设置文件也位于另一位置。

安装版可通过 Windows「已安装的应用／应用和功能」卸载。卸载会移除安装器登记的文件和快捷方式，保留程序自行生成的 `settings.xml` 和 `logs/`；需要彻底移除时，再自行删除剩余文件夹。便携版不会创建安装记录；关闭后移除对应文件夹即可。删除前如需保留配置和诊断记录，请先备份。

## 如何提供有用的反馈

提交 Issue 时，可以使用仓库中的问题模板，并提供：

1. GoggleCast 版本、Windows 版本、眼镜具体型号及固件版本。
2. 网络安排：路由器 Wi-Fi、电脑网线加眼镜 Wi-Fi，或电脑移动热点。
3. 投屏内容：桌面、测试画面、视频转码或原画直传。
4. 清晰度、编码模式、传输格式，以及声音从哪里收听。
5. 具体复现步骤、眼镜内实际现象和相关错误日志。

可在界面展开「连接日志」，点击「打开日志文件夹」。日志可能包含设备名称、网络地址和本地文件路径，公开前请脱敏。不需要提供网络密码、个人视频或完整桌面录制。

本项目独立于 DJI。Goggles 2 目前仅依据官方 DLNA 支持列为可尝试，Goggles N3 不列入当前支持范围。反馈时请明确实际型号、固件与耳机接口，不要直接把 Goggles 3 的结果视作通用兼容保证，详见 [兼容性说明](COMPATIBILITY.md)。
